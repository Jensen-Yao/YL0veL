# YL0veL 技术选型与开发路线图（v1.0）

> 状态：正式版（基于 2026-08-16 定稿的《调研报告》，两份文档相互引用）
> 目标平台：iPhone（主力）+ Apple Watch（配合）+ 小组件

---

## 1. 技术栈选型

### 1.1 客户端框架对比

| 维度 | SwiftUI 原生（推荐） | Flutter | React Native |
|---|---|---|---|
| HealthKit 深度集成 | ★★★ 一等公民 | ★★ 需桥接插件 | ★★ 需桥接插件 |
| watchOS 独立 App / complication | ★★★ WidgetKit 全支持 | ✗ 不支持 watchOS | ✗ 不支持 |
| 端侧语音 WhisperKit | ★★★ Swift Package 直接集成 | ★ 需原生桥接 | ★ 需原生桥接 |
| Apple Watch 温度/传感器 | ★★★ 原生 API | ✗ | ✗ |
| 开发速度（单人） | ★★ | ★★★ | ★★★ |
| 中文社区资料 | ★★ | ★★★ | ★★★ |

**结论：SwiftUI 原生。** 理由：Apple Watch 深度配合与 HealthKit 是核心需求，watchOS 上 Flutter/RN 无法交付；SwiftUI + SwiftData + Swift Charts 生产力已足够高。若未来需要安卓版，核心预测算法写成纯 Swift 包便于移植。

### 1.2 各层选型

| 层 | 选型 | 备选 | 说明 |
|---|---|---|---|
| UI | SwiftUI + Swift Charts | — | 日历、周期曲线、温度趋势图 |
| 本地存储 | SwiftData / GRDB (SQLite) | HealthKit 本身 | 经期记录以 HealthKit 为真源（可与 Apple 健康互通），App 自有元数据存本地库 |
| 健康数据 | HealthKit（读写 MenstrualFlow 等 + 读手腕温度/心率/HRV/睡眠） | — | 见调研报告第 3 节 |
| 预测引擎 | 自研 Swift 包：平均周期基线 + 手腕温度相位校准 | 参考 drip/log28 算法；后期轻量 ML（Create ML 表格回归） | 可解释、离线、无数据外传 |
| 语音识别 | M2 首版：SFSpeechRecognizer（在线中文，免费）；M2.5 增强：WhisperKit 或 whisper.cpp small（端侧离线，隐私增强） | — | 见调研报告 5.1 三路线对比 |
| 对话结构化 | 规则引擎（关键词/词表，离线兜底）+ LLM API（可选，JSON Schema 抽取） | 本地小模型 Qwen3（参考 WalkWrite） | 健康信息默认不外传 |
| Watch | watchOS 独立 App + complication/Smart Stack 快捷记录 | 语音听写（dictation） | 注意 WidgetKit complication 的 HealthKit entitlement 配置 |
| 提醒 | UNUserNotificationCenter 本地通知 | 经期预测、症状提醒、喝水/用药 | 全部本地生成，无需服务器 |
| 安全 | App 密码锁/FaceID、可选 iCloud 加密同步（CloudKit 私库） | 假 PIN（学 Euki） | 经期数据敏感，见调研报告 5.5 |

## 2. 功能模块拆解

```
YL0veL
├── 记录模块 Record
│   ├── 经期（开始/结束、流量分级、症状词表、情绪、备注）
│   ├── 每日健康（体温、用药、性行为、试纸结果、宫颈粘液）
│   └── 语音对话入口（一句话 → 结构化记录，含确认/纠错）
├── 预测模块 Predict
│   ├── 周期统计（平均长度、标准差、规律性评分）
│   ├── 下次经期预测（区间 + 置信度）
│   ├── 排卵窗口估计（周期法 + 手腕温度相位校准）
│   └── 手腕温度分析（偏离基线曲线、相位判定）
├── 守护模块 Guard
│   ├── 智能提醒（经期将至、排卵期、症状异常趋势提示）
│   ├── 健康趋势（心率/HRV/睡眠与周期叠加视图）
│   └── 关怀文案（Y💗L 风格，给她的温柔提醒）
├── 数据模块 Data
│   ├── HealthKit 同步（双向：App 记录 → 健康；手表传感器 → App）
│   ├── 导入/导出（JSON/CSV）
│   └── 备份（CloudKit 私库，端到端）
└── Watch 模块
    ├── complication 快捷记录（点一下记流量/症状）
    ├── 手表表盘展示：周期第几天、预测日期
    └── 手腕温度卡片
```

## 3. 开发路线（分阶段）

### M0 — 骨架（第 1~2 周）
- SwiftUI 工程 + SwiftData 模型（CycleLog、Symptom、DailyNote）
- HealthKit 授权流程 + 经期数据读写验证
- 日历视图（月视图、点击标记）
- 产出：能记录经期起止并显示日历的 iOS App

### M1 — 预测 MVP（第 3~5 周）
- 平均周期算法（历史长度统计 + 加权）
- 下次经期/排卵窗口预测 + 图表（Swift Charts）
- 本地通知提醒（经期前 1~3 天）
- 症状词表与情绪记录
- 产出：核心可用的经期预测 App（可先给女朋友试用）

### M2 — 语音对话（第 5~7 周）
- SFSpeechRecognizer 在线中文识别（Info.plist：NSSpeechRecognitionUsageDescription + NSMicrophoneUsageDescription）
- 语音 → 文本 → 规则引擎/LLM 提取结构化字段 → 预览确认卡 → 写入（参考 real-time-symptom-logging、dailyvox）
- 离线降级：WhisperKit/whisper.cpp small 中文模型（预下载）
- 产出：「今天来了，量少，有点肚子疼」一句话完成记录

### M3 — Apple Watch（第 7~9 周）
- watchOS 独立 App + complication 快捷记录
- 读取手腕温度（AppleSleepingWristTemperature）建立基线
- 温度偏离曲线 + 相位校准进预测引擎
- 产出：Apple Watch 全程配合（夜间自动采温度，白天一键记录）

### M4 — 守护与打磨（第 9~12 周）
- 心率/HRV/睡眠与周期叠加趋势
- 健康守护提醒（异常趋势提示，附「仅供参考」医疗免责）
- 隐私：App 锁、FaceID、CloudKit 私库同步
- Y💗L 品牌化 UI（粉色主题、暗色模式、动态岛/灵动小组件）
- 产物：可 TestFlight 分发的完整版

## 4. 关键风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| 手腕温度基线 | 需连续佩戴睡眠追踪约 5 晚建立基线；只有 S8+ 有传感器 | 首启动引导说明；无温度数据时降级为纯周期法 |
| 预测准确性 | 周期不规律时平均法误差大 | 输出「预测区间」而非单日；用温度相位做校正；文案诚实（不制造焦虑）；算法评估对齐 Curry 2025 口径 |
| 语音识别 | SFSpeechRecognizer 在线有配额、音频经 Apple 服务器；离线中文弱；Whisper 模型大 | M2 用在线版；M2.5 切 WhisperKit small 端侧增强并明示隐私策略 |
| HealthKit 授权繁琐 | 多类型分别授权，用户易拒 | 授权页分步引导，讲清每项用途 |
| LLM 隐私与成本 | 把健康信息发给第三方 API 需征得同意 | 默认规则引擎离线解析；LLM 可选且明示；后期可切本地小模型 |
| 医疗合规 | 预测≠医疗诊断 | 显著免责声明；异常提醒措辞为「建议咨询医生」 |
| watchOS 开发坑 | WidgetKit complication + HealthKit entitlement 配置 | 调研报告已记录官方论坛踩坑帖，开发时先跑通最小样例 |

## 5. 下一步决策点（待用户拍板）

1. 客户端框架确认 **SwiftUI 原生**（若女票无 Apple Watch 且要多端，可改 Flutter，参考 Menstrudel）
2. 语音是否接受「M2 在线识别起步、M2.5 端侧增强」的隐私路线
3. LLM 用哪个 API（DeepSeek / 通义 / 本地小模型 Qwen3）；默认规则引擎离线解析
4. M1 阶段是否需要云端同步（建议 M4 再做，CloudKit 私库）
5. 借鉴策略：开源项目代码可直接复用后修改，不设许可限制（已按此执行）
