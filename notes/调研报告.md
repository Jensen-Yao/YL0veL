## 3. Apple 生态集成（已核实要点）

### 3.1 HealthKit 经期数据类型（完整清单）

| 类型 | 标识符 | 读写 | 说明 |
|---|---|---|---|
| 经血量 | `HKCategoryTypeIdentifierMenstrualFlow` | 读+写 | 经期记录核心类型，行业落库标准；枚举 `unspSpecified/light/medium/heavy`（Flo/Clue 均落此类型） |
| 宫颈黏液质量 | `HKCategoryTypeIdentifierCervicalMucusQuality` | 读+写 | 排卵监测辅助 |
| 排卵试纸结果 | `HKCategoryTypeIdentifierOvulationTestResult` | 读+写 | 阳性/阴性 |
| 性行为 | `HKCategoryTypeIdentifierSexualActivity` | 读+写 | 生育/避孕辅助 |
| 经间期出血 | `HKCategoryTypeIdentifierIntermenstrualBleeding` | 读+写 | iOS 16+ |
| 基础体温 BBT | `HKQuantityTypeIdentifierBasalBodyTemperature` | 读+写 | 量样本（非 category），单位 ℃ |
| 周期偏差因子 | irregular/infrequent cycles、prolonged periods 等 | **只读** | iOS 16+ 系统自动计算的风险提示 |

官方文档：[HKCategoryTypeIdentifierMenstrualFlow](https://developer.apple.com/documentation/healthkit/hkcategorytypeidentifier/menstrualflow)、[HKCategoryTypeIdentifier 全枚举](https://developer.apple.com/documentation/healthkit/hkcategorytypeidentifier)
- 授权：Info.plist `NSHealthShareUsageDescription`（读）/ `NSHealthUpdateUsageDescription`（写）+ Xcode HealthKit capability；用户可随时撤销；不得用于广告/出售。临床记录 key（`NSHealthClinicalHealthRecordsShareUsageDescription`）本 App 不需要
- 架构建议：把 HealthKit 数据镜像到本地库（SwiftData）避免频繁全量查询；用户撤销授权后做降级体验（本地数据仍可用，仅停止同步）
- 注意：Apple 官方「经期预测日期」与「排卵回溯估计结果」**不通过 HealthKit 导出**（StackOverflow 已确认），预测需自研——手腕温度原始数据则是可读的
- 参考：iOS 26 上 [HealthKit + SwiftUI 模式](https://blakecrosley.com/blog/healthkit-swiftui-patterns-ios-26)、[HealthKitUsageDemo](https://github.com/apdevzhang/HealthKitUsageDemo)

### 3.2 手腕温度与排卵回溯估计（Apple Watch 核心卖点）

- API 准确名称：**`HKQuantityTypeIdentifierAppleSleepingWristTemperature`**（iOS 16.0+/watchOS 9.0+），每个睡眠会话一个 `HKQuantitySample`（℃）；第三方**只能读聚合样本**
- 官方：[夜间手腕温度变化跟踪](https://support.apple.com/zh-cn/102674)（Apple Watch Series 8/9/10/Ultra，SE 无传感器）；需连续佩戴睡眠追踪约 5 晚建立基线，健康 App 显示「相对基线的变化」
- Apple 官方 Cycle Tracking 提供「回顾性排卵估算」（retrospective ovulation estimates，事后修正而非实时），但算法闭源、结果不导出
- 已知坑：第三方 App 读到的温度值存在与健康 App 显示不一致的情况（[StackOverflow](https://stackoverflow.com/feeds/question/77556769)），开发时需与健康 App 对照验证
- **结论：YL0veL 自己用「手腕温度偏离基线」做周期相位估计是可行且差异化的**；算法评估口径可对标 Curry 等 2025《Human Reproduction》研究（见 4.2）

### 3.3 watchOS 形态与关键限制

- watchOS 9+ 支持**独立 watch App**（自带 HealthKit entitlement 与授权）；watchOS 10+ 复杂功能改用 **WidgetKit**（ClockKit 废弃），可深链到快捷记录页；注意 WidgetKit complication 需要 HealthKit entitlement（[官方论坛踩坑帖](https://developer.apple.com/forums/thread/719434)）
- **关键限制：手表本地只保留最近窗口的健康数据（约一周），watch 端类型支持是子集** → 架构定为「手表采集/快捷记录，iPhone 全量分析」
- 手表录音：`SFSpeechRecognizer`（watchOS 6+）+ `WKExtendedRuntimeSession`（屏灭续命，有时长上限）；同步用 `WCSession` 或经 iCloud 健康同步
- 另有 Siri Shortcuts 入口可做「Hey Siri，记录我今天的经量」类快捷指令
- 推荐形态：iPhone 主 App + watchOS 独立 App（complication 一键记录 + 表盘显示周期天数/预测）+ Smart Stack 小组件

## 4. 预测算法方向（已核实部分）

1. **经典统计法**（drip / log28 思路）：基于历史周期长度均值 ± 方差，预测下次经期与排卵窗口；优点是透明、离线、可解释
2. **手腕温度法**：周期中黄体期体温升高（约 0.3–0.5 °C），连续监测可得排卵后确认与下次经期预测（与 Apple 官方方法一致）
3. **心率 / HRV 法**：研究证实月经周期各相位心率与 HRV 有规律性变化
   - [Wearable Sensors Reveal Menses-Driven Changes in Physiology and Enable Prediction of the Fertile Window](https://www.ncbi.nlm.nih.gov/m/pubmed.mobile/30998226/)（JMIR）
   - [Tracking Sleep, Temperature, Heart Rate, and Daily Symptoms Across the Menstrual Cycle with the Oura Ring](https://pmc.ncbi.nlm.nih.gov/articles/PMC9005074/)（Nature Digital Medicine）
4. **ML 回归**：周期长度预测、排卵日预测（见 2.2 中 Menstrual_Cycle_Analysis 等）

### 4.1 源码级实锤（已克隆 drip + log28 到 `references/` 并读源码）

**drip（GitLab bloodyhealth/drip）`lib/cycle.js` → `getPredictedMenses()`：**
- 前置条件：至少 3 个完整周期（`minCyclesForPrediction`，可配置为 1）；周期 > 99 天（`maxCycleLength`）的异常周期剔除
- 统计量：`getCycleLengthStats()` 计算 min/max/**mean**/median/**无偏样本标准差**
- 预测：`periodDistance = round(mean)`；未来 3 次经期，每次输出一个**预测窗口**：σ < 1.5 → ±1 天（3 天窗口），否则 ±2 天（5 天窗口）
- 保护：预测区间过窄会重叠时放弃预测
- 数据模型（`db/schemas/1.js`）：CycleDay（以日期为主键）→ bleeding（流量分级）/ pain（cramps 痛经、ovulationPain、headache、backache、nausea、tenderBreasts、migraine）/ mucus（feeling+texture+value）/ temperature / cervix / sex（+避孕方式）/ note / desire —— 这是可直接借鉴的症状词表蓝本
- 无 HealthKit 集成（本地 Realm + 手动导出）
- 提醒设计（`lib/notifications.js`）：体温每日定时提醒（点击直达编辑页）；经期提醒 = 预测窗口首日 −N 天（可配置提前量）早 6 点推送，文案带预测区间「经期预计在 X~Y 天后开始」；经期数据变化自动重排提醒 —— 可直接照搬此交互

**log28（wildeyedskies/log28）`CalendarView.kt` → `predictFuturePeriods()`：**
- 号称 AI 预测，实为**纯平均周期法**：mean(cycleLength) + mean(periodLength)，预测未来 3 次经期起止日；无置信区间，代码里还有 off-by-1 TODO
- 结论：开源界"经期预测"主流是统计法，ML 多为营销或学术实验

### 4.2 算法共识与研究参考

- **领域共识**：排卵日 ≈ 周期长度 − 黄体期（12–16 天）；下次经期 ≈ 排卵日 + 14 天；BBT 持续升温 3 天确认排卵（开源界与 drip 一致）
- **先验校准**：Soumpasis 2020（Natural Cycles 大数据，真实周期分布）→ 用「人群先验 + 用户历史贝叶斯更新」，用户周期数少时预测更稳
- **手腕温度权威研究**：Curry 等 2025《Human Reproduction》（doi:10.1093/humrep/deaf005）——手腕温度排卵回溯 + 下次经期预测算法评估，**建议作为 YL0veL 算法的评估口径对标**：回溯排卵日误差、下次经期 ±3 天命中率（[Semantic Scholar](https://www.semanticscholar.org/paper/Performance-of-algorithms-using-wrist-temperature-a-Wang-Park/885d8e13d1108dfb4dc0ccb9baf8f333425fbc15)）
- **可移植库**：[yc-fam-js](https://www.npmjs.com/package/yc-fam-js)（症状-体温法 JS 库，含 BBT/黏液规则，可参考移植为 Swift）；the-period-purse（[预测实现讨论](https://github.com/uoftblueprint/the-period-purse-android/issues/24)）
- 开源 ML：WiselyAndHealthy（深度学习）、[MenstrualCyclePrediction](https://github.com/chiomajaco6/MenstrualCyclePrediction)、[Menstrual_Cycle_Analysis](https://github.com/dwninii/Menstrual_Cycle_Analysis)（多目标回归）、Monthly-Ovulation-Prediction-matlab

> 选型倾向（确定）：MVP 用「drip 式 mean±σ 预测窗口 + 手腕温度相位校准」的混合模型（可解释、隐私好、有源码可参考）；积累 6+ 周期数据后再评估轻量 ML；算法评估对齐 Curry 2025 口径。

### 5.4 落地管线（YL0veL 版）

```
录音(AVAudioSession .record) → ASR（在线 SFSpeechRecognizer，离线降级 WhisperKit small）
→ 规则引擎解析（关键词/正则：日期、流量、症状词表）→ 失败则 LLM（JSON Schema 抽取）
→ 预览确认卡（可改）→ 写 SwiftData + HealthKit
```

- 默认规则引擎离线解析保证「没网也能用」；LLM 可选（用户自配 API key 或本地小模型），健康信息不外传为默认
- 参考 femtracker-agent 的 LLM+领域知识设计（见 2.2）

## 5.5 隐私与趋势（重要背景）

- 经期数据属高度敏感个人信息（中国《个保法》敏感个人信息范畴；国际上 post-Roe 背景下经期数据安全尤为敏感）
- 开源社区主流趋势是 **local-first / privacy-first**：drip、Euki、Mensinator、ovumcy、Lunavi、Mooneva、Dew 等全部主打「数据不出本地」
- **对 YL0veL 的含义**：默认本地存储（HealthKit + SwiftData/SQLite），云端同步做成可选且端到端加密；语音识别用端侧 WhisperKit（不把音频上传第三方）——「守护」的第一层就是隐私守护

## 6. 结论与下一步

1. **市场空位**：没有现成的「经期 + 健康守护 + 语音 + Apple Watch」一体化开源项目可直接套用；中文开源经期项目几乎空白。各模块均有成熟开源组件可拼装——「组装式创新」，可行性高
2. **差异化定位（建议）**：**Apple Watch 手腕温度驱动的周期预测 + 语音对话记录 + 隐私本地优先 + 中文关怀体验**；且「HealthKit 读写 + 手腕温度分析」在开源界是空白（见 2.1 结论），先发优势明确
3. **算法路线（确定）**：M1 用 drip 式「mean±σ 预测窗口」统计法（源码已克隆可参考），M3 叠加手腕温度相位校准，算法评估对齐 Curry 2025《Human Reproduction》口径；ML 待 6+ 周期数据后再评估
4. **语音路线（确定）**：M2 用 SFSpeechRecognizer 在线中文（免费）+ 规则引擎离线解析；M2.5 叠加 WhisperKit/whisper.cpp small 端侧识别与可选 LLM（JSON Schema 抽取），健康信息默认不外传
5. **平台路线（建议）**：SwiftUI 原生（HealthKit/watchOS 一等公民），iPhone 主 App + watchOS 独立 App + 小组件
6. 详细排期、风险与决策点见 [开发路线图](开发路线图.md)
